## Failure Matrix Overview

The table below details the expected behavior, data-integrity guarantees, tenant-isolation invariants, and recovery mechanisms for all 20 critical platform failure modes.

| # | Failure Scenario | Detection Mechanism | Operational Impact | Recovery Mechanism | Expected Recovery Time | Data Integrity Expectation | Tenant Isolation Expectation | Auto / Manual | Observability Signal |
| :- | :--- | :--- | :--- | :--- | :---: | :--- | :--- | :---: | :--- |
| **1** | **MongoDB Unavailable** | Readiness probe ping timeout, connection error event | Read/write requests fail with HTTP 500/503; API enters degraded/unavailable state | Mongoose automatic driver reconnection backoff; traffic drained by load balancer | < 15s after DB online | Zero corrupted partial writes; in-flight transactions abort cleanly | Preserved; fail-closed | Auto | Log `[UNHANDLED ERROR] MongoServerSelectionError`, Readiness `status: UNAVAILABLE` |
| **2** | **MongoDB Slow (WAN latency spike)** | Express request logger `durationMs > 2000`, DB ping latency | API response times degrade, queue backlog increases | Query timeout (`serverSelectionTimeoutMS: 10000`, `socketTimeoutMS: 45000`), client retry | Immediate upon latency drop | In-flight queries complete or timeout safely without state divergence | Preserved; queries remain tenant-indexed | Auto | Log `[WARN] Slow Query`, `requestId`, `durationMs` spike |
| **3** | **MongoDB Connection Pool Exhaustion** | Active connections = 50 (`maxPoolSize`), waiting request queue spike | New queries queued or reject with `PoolClearedError` / timeout | Connection pool recycling, client timeouts shed excess load | < 5s after burst settles | Zero corrupted writes; rejected queries throw clean errors | Preserved; no cross-connection state sharing | Auto | Log `PoolClearedOnNetworkError` or connection timeout |
| **4** | **Redis Unavailable** | Redis error event (`ECONNREFUSED`), `getRedisStatus()` | BullMQ distributed queues stall; transactional emails fallback to in-process async | Degraded mode fallback: emails sent inline/async; scheduler avoids duplicate crons | < 2s to degraded fallback | Zero financial loss; transactional email jobs logged in-process | Preserved; tenant context in payload preserved | Auto | Log `[Redis] connection warning: DEGRADED`, Readiness `dependencies.redis.status: DEGRADED` |
| **5** | **Redis Slow** | Command timeout on Redis client, BullMQ job latency | Queue enqueue/dequeue latency increases | IORedis connectTimeout (10s), BullMQ retry backoff | Immediate upon Redis recovery | Zero corrupted queue data | Preserved | Auto | Log `[Redis] Command timed out` |
